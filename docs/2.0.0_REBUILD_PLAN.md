# ChessBuddy 2.0.0 — Rebuild Contract

## Product direction

A complete, polished chess app with an original ChessBuddy identity and familiar chess-app interaction patterns. Do not copy Chess.com's proprietary source, branding, private assets, or claim affiliation. Use original UI, original bot portraits, and clearly labeled compatibility/integration features.

## Required product areas

- Home/lobby: responsive dark interface, visible primary play action, quick time controls, resume game, bots, coaches, puzzles, learn, watch, online and analysis entry points.
- Board: legal moves, drag/tap input, promotion, clocks, increment, premoves where supported, sound, animations, board themes, coordinates, flip, resign/draw/rematch, move list and game-over states.
- Bots: 100+ selectable profiles, searchable/filterable by strength and personality, original portrait art, voice/narration controls, reliable engine mapping, AI-vs-AI. Distinguish locally calibrated estimates from official ratings. Do not label a ChessBuddy estimate as an exact Chess.com rating.
- Famous bot compatibility: Martin, Mittens and other recognizable bot concepts may be represented only with accurate public facts and original implementation/art; do not claim identical behavior or official endorsement. Verify every displayed rating against a current first-party public source before labeling it exact.
- Coaches: actual instructional content, level-specific lessons, annotated positions, practice tasks and progress tracking. A chat persona alone is not a real coach feature.
- Accounts: email signup/sign-in, verification, password recovery, Google OAuth, profile creation, session refresh, sign-out and useful error handling. Presence must only start after profile creation succeeds.
- Lichess: public opening explorer/tablebase where available, imports/exports and explicit connection status. Clearly distinguish Lichess public APIs from authenticated Lichess account features.
- AI-vs-AI: choose both players, engine/provider, strength, clock and side; watch the game with pause/step/speed controls.
- More chess tools: analysis, game review, PGN/FEN import/export, opening explorer, endgame practice, puzzles, studies/lesson path, archive, settings, accessibility, offline play and privacy controls.

## Release gates

1. No blank/white startup or home state on supported Android devices; add a startup smoke test and screenshot test.
2. Every visible control has a working action or is explicitly marked unavailable; no dead buttons.
3. Bot roster has unique IDs, stable avatar mapping, valid strength/provider mapping and tests for all profiles.
4. Voice uses platform TTS with per-bot voice/personality settings; animation state is tied to real app events, not decorative playback only.
5. Account flow is tested against the configured Supabase project with a new account, returning account, verification and recovery.
6. Lichess endpoints are tested live with clear offline/error handling.
7. AI-vs-AI runs a full legal game and supports stop/resume/step/speed.
8. Android CI builds and verifies the APK; test on at least one physical arm64 device.
9. Compressed source archive remains below 50 MB. APK size is tracked separately and must not be confused with source size.

## Baseline facts (2026-11-18)

- The Build 49 source archive is 319,357 bytes and contains 205 files; the complete Build 49 artifact also contains an approximately 81 MB APK.
- Existing source includes chess.js, Stockfish/Lc0 integration, a 150+ bot roster, AI-vs-AI logic, coach/chat logic, account UI and Lichess public-data calls.
- Existing tests currently pass: `node tests/run-all.js`, `bash tests/java/run.sh`, and shell syntax checks. These are not a substitute for Android device, live-auth, live-Lichess or online multiplayer tests.
- The `chessbuddy-2.0.0-rebuild` branch currently starts from the Build 49 commit. No 2.0.0 feature commit has been pushed yet.
- Sign-in UI and backend requests exist, but successful service authentication does not prove the complete new-user/profile/presence flow works. Verify the profile creation sequence against live Supabase before release.
- The generated 2.0 promotional image is a visual target only; it is not proof that those features are implemented.

## Implementation order

1. Startup/home rendering and full UI shell; fix the reported blank-white screen first.
2. Auth/profile creation and online presence ordering.
3. Bot catalogue, original raster portraits and reliable provider/voice/animation mapping.
4. Board/game UX and AI-vs-AI completeness.
5. Coach curriculum and Lichess integrations.
6. Puzzle/learning/review tools, accessibility, QA and release packaging.
